# Roadmap

This page lists the next steps that follow from [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md). It has **no dates and makes no promises**: it says what should come next, why, and how anyone would know it is done. The ids on the left (`R-1`, ...) are used for cross-references; the ids in the "Closes" column are the limitations from that page.

## How the order was chosen

1. **Prove before extending.** A feature built on an unproven integration adds risk, so the first tier is about running what already exists against the real thing.
2. **Remove the single points of failure** that lose or delay work: jobs that live in one process, limits that live in one replica.
3. **Enforce what is only stored.** Several settings and controls exist in the data model but nothing acts on them.
4. **Widen the claims last.** More workloads and more automation come after the evidence base is broader than two synthetic cases.

The order can change with what the first tier finds. A step is "done" only when the evidence named in its last column exists and the "mock-only" or "designed" label in the documents has been replaced by what was observed.

## Human actions

HA-1 to HA-10 in [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md#5-human-actions-required) are decisions and settings for the repository owner and for an operator with Azure credentials. They are not engineering tasks, but R-1 and R-2 depend on them.

## Not on the roadmap

These are non-goals of the prototype, repeated from [ARCHITECTURE.md](ARCHITECTURE.md#1-context-and-goals): real customer data, ranking or scoring people, automatic case closure and a ticketing system. Using real data would first need the work listed in [PRIVACY.md](PRIVACY.md#9-if-you-want-to-use-real-data-do-not-without-this-work).
