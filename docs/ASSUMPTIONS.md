# Assumptions

Assumptions made while the requirements were silent or ambiguous. Each can be revisited; the **Impact** column says what would change.

| ID   | Assumption                                                                                                                                                                                                                                               | Rationale                                                                                                                                      | Impact if wrong                                                                                                                                                                                                                                                                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A-01 | The hackathon audience evaluates a working local demo; no live Azure subscription is guaranteed                                                                                                                                                          | Credentials were not supplied; deploying costs money                                                                                           | Azure paths are implemented and statically validated only; documented as such                                                                                                                                                                                                                                                                                                                                 |
| A-02 | All case data is synthetic; synthetic bundles carry `"synthetic": true` and the UI labels them                                                                                                                                                           | Privacy and the explicit instruction not to use customer data                                                                                  | A tenant flagged `synthetic` (every seeded tenant) refuses `"synthetic": false` payloads; a tenant provisioned as non-synthetic accepts them after stricter redaction and flags `synthetic=false`                                                                                                                                                                                                             |
| A-03 | One logical tenant is seeded (`tenant_contoso_support`) and a second (`tenant_fabrikam_lab`) exists for isolation tests                                                                                                                                  | Tenant isolation must be demonstrable                                                                                                          | Single-tenant deployments simply use one tenant row                                                                                                                                                                                                                                                                                                                                                           |
| A-04 | Hypotheses are modelled as mutually exclusive plus an explicit "other / unknown" mass                                                                                                                                                                    | Keeps Bayesian updating explainable                                                                                                            | Co-occurring causes are under-represented; documented limitation                                                                                                                                                                                                                                                                                                                                              |
| A-05 | Evidence signals are treated as conditionally independent, dampened by a per-signal weight                                                                                                                                                               | Naive-Bayes style updating is transparent and testable                                                                                         | Correlated signals can over-weight a hypothesis; mitigated by dampening and uncertainty bands                                                                                                                                                                                                                                                                                                                 |
| A-06 | Likelihoods, priors, effort and cost figures in the knowledge pack are **illustrative estimates authored for the demo**, not Microsoft guidance or measured data                                                                                         | No authoritative dataset exists                                                                                                                | Output confidences are model estimates only and are always labelled so                                                                                                                                                                                                                                                                                                                                        |
| A-07 | Token counts for the deterministic provider are estimated as `ceil(chars / 4)`; no cost is reported unless the operator configures unit prices (A-16), and nothing is ever billed                                                                        | Honest, deterministic telemetry without a live model                                                                                           | Real numbers appear only when the Azure provider is configured                                                                                                                                                                                                                                                                                                                                                |
| A-08 | Time-to-diagnosis for the actual path is the first event at which the leading (non-`other`) hypothesis reaches the diagnosis threshold (default 0.75) **and** its confirmation requirements are satisfied, using only evidence available then            | A defensible, reproducible definition                                                                                                          | The threshold is a knowledge-pack policy (`diagnosisThreshold`), not a governance setting                                                                                                                                                                                                                                                                                                                     |
| A-09 | Customer response latency in counterfactual simulation uses a configured prior (default 90 minutes, range 45–180), never the observed future reply time                                                                                                  | Prevents temporal leakage                                                                                                                      | Estimates are labelled as assumptions with ranges                                                                                                                                                                                                                                                                                                                                                             |
| A-10 | The skill-guided second case is an authored synthetic case; improvement figures demonstrate the measurement pipeline, not real-world effectiveness                                                                                                       | There is no real population of engineers                                                                                                       | UI and docs carry an explicit synthetic-effectiveness notice                                                                                                                                                                                                                                                                                                                                                  |
| A-11 | PGlite is acceptable for local/test persistence; production uses PostgreSQL                                                                                                                                                                              | Removes Docker as a hard prerequisite                                                                                                          | CI is defined to run the integration suite on real PostgreSQL 16 (`.github/workflows/ci.yml`; that path has not been observed running)                                                                                                                                                                                                                                                                        |
| A-12 | A single-process in-memory job runner is sufficient (no external queue)                                                                                                                                                                                  | Modular monolith; bounded workloads                                                                                                            | Horizontal scale would need a queue (documented in roadmap)                                                                                                                                                                                                                                                                                                                                                   |
| A-13 | Rate limiting and caching are in-memory; a Redis cache provider is reserved in configuration but **not implemented**                                                                                                                                     | Cost-conscious defaults                                                                                                                        | Multi-replica deployments would need a shared store for limits and caches (not implemented); which address a limit counts is A-19 and A-20                                                                                                                                                                                                                                                                    |
| A-14 | Development persona authentication is only available when `APP_ENV` is `local` or `test`; `development`, `staging`, `production` and unknown values are refused                                                                                          | Prevents accidental insecure production deploys                                                                                                | The authenticator refuses to start otherwise, and configuration validation also fails outside `local` and `test`                                                                                                                                                                                                                                                                                              |
| A-15 | Microsoft Entra ID integration validates JWTs and maps app roles; it has not been exercised against a live tenant here                                                                                                                                   | No tenant/credentials available                                                                                                                | Documented setup steps; unit-tested with locally generated keys                                                                                                                                                                                                                                                                                                                                               |
| A-16 | Pricing is never hard-coded; cost figures in the product are token-based estimates from configurable unit prices                                                                                                                                         | Azure pricing varies by region, date, agreement and SKU                                                                                        | Operators must supply current prices                                                                                                                                                                                                                                                                                                                                                                          |
| A-17 | Time zones: all timestamps are stored and compared in UTC                                                                                                                                                                                                | Avoids the ambiguity that plagues log correlation                                                                                              | UI renders in the viewer's locale with explicit UTC offsets                                                                                                                                                                                                                                                                                                                                                   |
| A-18 | The repository was initially empty and the first push created the default branch, `feat/caseguard-ai-platform`; on 8 November 2026 `main` was created and became the default branch                                                                      | Observed via `gh repo view`                                                                                                                    | A base branch must be approved before a PR can be opened                                                                                                                                                                                                                                                                                                                                                      |
| A-19 | In Azure the API container app has internal ingress and its only caller is the web app, so `TRUST_CLIENT_IP_HEADER=true` is safe there: every `x-cg-client-ip` the API receives was set by the web server, which first deletes any value the client sent | Visitors must be throttled individually; without the header the API sees only a web replica's address and every visitor would share one bucket | If browsers or any other caller could reach the API directly, they could choose their own rate-limit bucket. No configuration guard prevents enabling the flag, so it must stay off (the default) for any such API                                                                                                                                                                                            |
| A-20 | The right-most `x-forwarded-for` entry the web server receives is the visitor's address as appended by the Azure Container Apps ingress, and the ingress passes request headers on unchanged                                                             | The web tier reads only that last entry and ignores everything to its left, which the client controls                                          | Implemented and tested with simulated headers only; never observed behind a real ingress. If another proxy (for example Front Door) sat in front of the ingress, the right-most entry would be that proxy and all visitors would share one bucket; if no entry were appended, a client could choose its bucket. Deployment check 12 in [DEPLOYMENT.md](DEPLOYMENT.md#57-post-deploy-smoke-tests) detects both |
