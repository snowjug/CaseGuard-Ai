# Known limitations

This page lists what CaseGuard AI does not do, does only approximately, or has not proven. It is written for judges and for the engineer who inherits the code. It is not a list of bugs: each item is a decision, a gap in validation or a piece of work that was left out on purpose. [ROADMAP.md](ROADMAP.md) turns the items into next steps; the ids (`VG-1`, `PL-3`, ...) are what it refers to.

**How it was checked.** Every item was compared with the code of the working tree when this page was written, and the "Checked in" column names the file, test or document that shows it. Items that rest on reasoning rather than on a run say "reasoned only". Figures from the latest fully green CI run (GitHub Actions run 41495498658, on the unmerged branch `build/p0-foundation`: test, build, end-to-end and accessibility results) are recorded in the [Running tests](../README.md#running-tests) section of the README and in [CI_CD.md](CI_CD.md#9-what-was-and-was-not-validated); this page repeats only the few that an item depends on.

**The short version.**

- The product is a working prototype on **synthetic data only**, with the **deterministic AI provider** as its default and as what the demo uses.
- Azure OpenAI, Entra ID, Blob Storage and AI Search are **implemented but validated against local mocks only**. The Application Insights export is **implemented but optional and validated against fakes only** (OP-8): it is off unless a connection string is set, covers request spans and metrics but not logs or dependencies, and was never observed in Azure; the API logs to stdout. **Nothing has been deployed to Azure.** Docker image builds were not run locally; CI builds both images, and CI is fully green only on the unmerged branches (first green run 41495498658), not on the default branch.
- Every score, range and simulated outcome is an **estimate** from authored priors, shown with its basis and a label.

## 3. Security and privacy limits

| Id    | Limitation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Checked in                                                                                                                                         |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| SP-1  | **Synthetic data only, and the label is self-attested.** A tenant flagged synthetic refuses a payload that says `"synthetic": false`, but a payload that says `true` is believed. Real customer data must not be used: DLP, per-tenant keys and tenant provisioning are out of scope.                                                                                                                                                                                                                    | [PRIVACY.md](PRIVACY.md#3-keeping-real-data-out-synthetic-data-policy)                                                                             |
| SP-2  | **Redaction is pattern-based.** It misses names, free-text personal data and context-dependent secrets. Detection folds full-width forms, invisible characters and Unicode spaces, but not look-alike letters from other scripts (Cyrillic U+0430 for Latin `a`), combining marks or ligature expansions, so a secret written with them is not recognised. A tenant's custom pattern that cannot be applied refuses the ingest (fail closed).                                                            | [SECURITY.md](SECURITY.md#72-redaction-redacttext-redactvalue), `packages/security/src/redaction/fold.ts`                                          |
| SP-3  | **Large bundles with a custom pattern stall the event loop.** One measured run of a 2,000-event, 1.83 MB bundle with a single custom pattern took about 0.7 s (about 21 s before the batching rework), with a stall of up to about 0.9 s on very large bundles. A single local run, not part of the repeatable benchmarks.                                                                                                                                                                               | [SECURITY.md](SECURITY.md#72-redaction-redacttext-redactvalue)                                                                                     |
| SP-4  | **Malware scanning is a hook, not a scanner.** `NoopMalwareScanner` reports `not_scanned`; an EICAR test scanner exists as a test hook and is refused in production. No antivirus engine is integrated. Uploads are still limited to five text extensions and decided from their bytes.                                                                                                                                                                                                                  | [SECURITY.md](SECURITY.md#71-uploads-validateupload)                                                                                               |
| SP-5  | **Prompt-injection screening flags; it does not block.** It is heuristic and can be evaded. The controls that do not depend on detection (a model with no tools, delimited untrusted content, strict output schemas, seven validators, deterministic fallback) are the real defence, and a real model has never faced them.                                                                                                                                                                              | [SECURITY.md](SECURITY.md#74-prompt-injection), [AI_ORCHESTRATION.md](AI_ORCHESTRATION.md)                                                         |
| SP-6  | **The development persona login has no authentication.** Anyone who can reach the API can send `x-cg-persona`, so it is for synthetic data on a developer machine only. Configuration and the authenticator both refuse it unless `APP_ENV` is `local` or `test` (`development`, `staging` and `production` need Entra), and `NODE_ENV=production` with `APP_ENV` unset stops start-up, so the only place it exists is a local or test run.                                                              | [SECURITY.md](SECURITY.md#21-development-personas)                                                                                                 |
| SP-7  | **`TRUST_CLIENT_IP_HEADER` has no guard.** When it is `true` the API believes the `x-cg-client-ip` header. Nothing stops it being enabled on an API that browsers can reach directly, where a client could pick its own rate-limit bucket. The template sets it only for the internal API.                                                                                                                                                                                                               | `packages/config/src/sections/http.ts`; [SECURITY.md](SECURITY.md#client-address-for-rate-limits)                                                  |
| SP-8  | **The web tier shows the internal API address.** For a rewrite to an external URL, Next adds an `x-middleware-rewrite` header to the response, so a browser can read `API_INTERNAL_URL` (an internal address only). Avoiding it means forwarding with a route handler instead of a rewrite, or stripping the header at the ingress.                                                                                                                                                                      | `apps/web/README.md` (known limitations), `apps/web/src/proxy.test.ts`                                                                             |
| SP-9  | **The OpenAPI document and Swagger UI are served in more environments than the word "deployed" suggests.** They are hidden only when `APP_ENV` is `staging` or `production`, so the internet-facing `development` environment serves them too. They list routes, not data.                                                                                                                                                                                                                               | `apps/api/src/http/openapi.ts`, `packages/config/src/load.ts`                                                                                      |
| SP-10 | **A client-chosen request id becomes the audit correlation id.** The `x-request-id` header is validated (8 to 64 URL-safe characters) and echoed, so a caller can choose the correlation id stored with its own audit events. Denial events are throttled to one per caller and route per rate-limit window, with a counter for the ones left out.                                                                                                                                                       | `apps/api/src/http/route-binder.ts`, [API.md](API.md#request-identifiers-and-headers)                                                              |
| SP-11 | **Reasons typed for an export or a role change are not stored.** They are validated and used, but kept out of the audit event on purpose (the audit trail is immutable, so it holds ids, counters and enums only).                                                                                                                                                                                                                                                                                       | `apps/api/src/services/governance/README.md`                                                                                                       |
| SP-12 | **The audit hash chain is tamper-evident, not tamper-proof.** Head hashes are not anchored outside the database, so someone who can write to the database as its owner could rewrite the chain consistently.                                                                                                                                                                                                                                                                                             | [DATA_MODEL.md](DATA_MODEL.md#11-immutability-erasure-and-retention-what-exists), [SECURITY.md](SECURITY.md#12-what-this-does-not-protect-against) |
| SP-13 | **Retention is stored, not enforced.** The retention windows (case data, audit, model executions, analytics, legal hold) are validated, versioned and audited, but no job reads them. Erasure is a per-case administrator action; erasing a case does not erase the skills derived from it. Bulk erasure by age, archival and backup or restore are not implemented.                                                                                                                                     | [DATA_MODEL.md](DATA_MODEL.md#11-immutability-erasure-and-retention-what-exists), [PRIVACY.md](PRIVACY.md#7-retention-erasure-and-deletion)        |
| SP-14 | **A governance setting that nothing reads.** `redaction.redactBeforeModelCalls` is stored and defaults to true, but no code consults it: redaction of the text that reaches a model is unconditional, so the switch gives a false impression of control.                                                                                                                                                                                                                                                 | `packages/schemas/src/governance.ts`; [PRIVACY.md](PRIVACY.md#4-redaction)                                                                         |
| SP-15 | **The demo guard follows demo mode, not only the synthetic flag.** `demo.seed` and `demo.reset` are refused unless `DEMO_MODE` is on **or** the tenant is flagged synthetic; in demo mode the flag is not consulted, so an administrator can reset the case data of their own tenant even when it is not flagged synthetic. | SP-16 | **A time-boxed exception for a HIGH advisory.** `@azure/msal-node` 6.x (GHSA-xcx6-jx8p-x3h5, pulled in by `@azure/identity`) is excepted until 2027-01-15 because CaseGuard never calls the affected flow; it needs a human to accept the risk or to upgrade (HA-8).                                                                                                                                                                                                                                     | `docs/dependency-exceptions.json`, [SECURITY.md](SECURITY.md#10-dependency-policy-and-supply-chain)                                                |

## 4. Operational limits

| Id    | Limitation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Checked in                                                                                                                                                                               |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OP-1  | **Jobs run in the API process.** Concurrency is 2, the queue is in memory, there is no external queue and no worker pool. A job has a 10-minute limit; a heartbeat every 10 seconds lets another replica fail a job whose owner has been silent for 60 seconds as orphaned, and the work is not resumed. A durable queue with separate workers is the next step.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | [DATA_MODEL.md](DATA_MODEL.md#9-jobs), `apps/api/src/services/job-service.ts`                                                                                                            |
| OP-2  | **Limiters and caches are per replica and in memory.** The general and heavy rate limits, the denial-audit throttle, the as-of engine budget, the views and counterfactual caches, the identity-sync cache and the AI semantic cache are not shared between replicas and start empty after a restart. A shared cache is reserved but not implemented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `apps/api/src/services/engine-budget.ts`, `apps/api/src/identity-sync.ts`, `apps/api/src/http/denial-throttle.ts`                                                                        |
| OP-3  | **An engine pass blocks the event loop.** It is synchronous, so while it runs nothing else is served; the budget (30 cold passes per user per minute) and the caches bound how often, not how long. A typical sample case takes a fraction of a second; the largest input the parser accepts (2,000 events) took about 17 s of CPU in the hostile-input benchmark. A ReDoS probe over pattern-derived inputs found two first-party patterns that took 0.4 to 9.8 s on one crafted 20,000-character event; both are now bounded, and the probe is part of the domain suite, but it covers derived inputs, not every possible one.                                                                                                                                                                                                                                                                                                                                                                                                                | [EVALUATION.md](EVALUATION.md#6-performance), `apps/api/src/services/views/README.md`                                                                                                    |
| OP-4  | **Migration 0010 fails on duplicate references.** A database that already holds two cases of one tenant with the same reference refuses the migration (all or nothing); the runner names the constraint and the database README gives the repair query.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | `apps/api/src/db/README.md`                                                                                                                                                              |
| OP-5  | **Idempotency edge cases.** If storing the response fails after the work was committed, the key stays reserved until its reservation expires (5 minutes) rather than risking a repeated mutation. The purge and the erasure link rest on PostgreSQL locking that was only reasoned about (VG-7).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `apps/api/src/http/idempotency.ts`, [DATA_MODEL.md](DATA_MODEL.md#8-idempotency)                                                                                                         |
| OP-6  | **Stored objects can be orphaned.** The payload is written to the object store before the database transaction. A crash in between leaves an object that no case refers to, and nothing sweeps them (a failed discard is logged as `ingest.orphaned_object`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `apps/api/src/services/ingestion/persist.ts`                                                                                                                                             |
| OP-7  | **Tenant provisioning is validated on PGlite only.** The migration job creates the tenants named by `ENTRA_TENANT_MAP` (and `--tenant`) with default settings, idempotently. Tested as a non-superuser owner on PGlite, never on PostgreSQL 16 or Azure. It creates no users, so the demo personas (smoke check 10) are missing, and no audit event records who provisioned a tenant.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | [DEPLOYMENT.md](DEPLOYMENT.md#55-migrations), `apps/api/src/db/provision.ts`                                                                                                             |
| OP-8  | **Telemetry export is optional, partial and never observed in Azure.** The API exports request spans (`AppRequests`, and `AppExceptions` for 5xx) and the product metrics (`AppMetrics`) to Application Insights, but only when `APPLICATIONINSIGHTS_CONNECTION_STRING` is set (the Bicep template always sets it, so a deployment exports). It was validated against fakes and one local run of the real SDK against a loopback stand-in, never against Azure. Not exported: logs (they reach Log Analytics as container stdout), dependencies (`AppDependencies`: the automatic instrumentation is off and would not be expected to work in native ESM without the loader hook, and no service uses `withSpan`) and browser telemetry; the web tier is not instrumented.
